# 写作示范

## 仓储系统查询采购单收货记录

### 1.1 接口说明

采购工作台打开订单收货页时，按采购单号查询收货记录。以下接口用于教学。

| 项目 | 说明 |
| --- | --- |
| 调用方 | 采购工作台 |
| 接收方 | 仓储系统 |
| 请求方式 | GET |
| 接口路径 | `/warehouse/receipts` |

### 1.2 输入参数

| 查询参数 | 含义 | 类型 | 必填条件 | 取值来源 |
|---|---|---|---|---|
| `orderNo` | 采购单号 | 字符串 | 每次必填 | 取所选采购单详情的 `orderNo`，翻页时保持原值 |
| `cursor` | 续查游标 | 字符串 | 首次省略，继续翻页时必填 | 原样传上一页响应的 `nextCursor` |

### 1.3 报文示例

首次查询。

```http
GET /warehouse/receipts?orderNo=PO-20261125-0867 HTTP/1.1
Host: warehouse.example
```

### 1.4 返回参数

HTTP `200` 表示查询成功。取 `receipts` 展示收货记录。返回 `nextCursor` 时可继续查询，省略时结束翻页。

| 字段路径 | 含义 | 类型 | 何时返回 | 返回时可为 null |
|---|---|---|---|---|
| `receipts` | 当前页收货记录 | 对象数组 | 每次成功，查无记录为 `[]` | 否 |
| `nextCursor` | 下一页游标 | 字符串 | 仅有下一页时 | 否 |

**收货明细 `receipts[]`**　每一项对应一张收货单。

| 字段路径 | 含义及用途 | 类型 | 何时返回 | 返回时可为 null |
|---|---|---|---|---|
| `receipts[].receiptNo` | 收货单号，打开收货单时取该值 | 字符串 | 每条记录 | 否 |
| `receipts[].orderNo` | 所属采购单号，对应请求的 `orderNo` | 字符串 | 每条记录 | 否 |
| `receipts[].amount` | 本张收货单金额，单位为元，保留两位小数 | 字符串 | 每条记录 | 否 |

```json
{
  "receipts": [
    {
      "receiptNo": "GR-20261125-0472",
      "orderNo": "PO-20261125-0867",
      "amount": "168.40"
    }
  ],
  "nextCursor": "rcpt_A0472"
}
```

取本页 `nextCursor` 后，下一次请求为：

```http
GET /warehouse/receipts?orderNo=PO-20261125-0867&cursor=rcpt_A0472 HTTP/1.1
Host: warehouse.example
```

### 1.5 失败原因与重试处理

| HTTP | 错误码 | 原因 | 调用方处理 |
| --- | --- | --- | --- |
| 400 | `CURSOR_ORDER_MISMATCH` | 游标与采购单不匹配 | 展示 `message`，用当前采购单号重新查询首页。 |

```json
{
  "code": "CURSOR_ORDER_MISMATCH",
  "message": "续查游标不属于当前采购单"
}
```

错误体的 `code` 和 `message` 均为必返、非空字符串。程序按 `code` 分支，`message` 用于显示。

## 医保门诊结算撤销的关联取值（协议节选）

依据《医疗保障信息平台定点医药机构接口规范》V1.1.91 公共报文表 3～5、交易 2207A 表 119 和交易 2208 表 121～123。下列路径用于定位公共报文中的业务数据。这里只示范原交易关联与撤销结果的读法，完整接入还需使用相应版本公共报文的必填字段。

当医药机构需要撤销一笔已完成的门诊结算时，向地方医保局发起 `2208`。以原交易为 `2207A` 为例，原交易成功后保存同一条结算记录的三个标识，撤销时分别传回。

| 2208 请求路径 | 类型与长度 | 必填条件 | 原交易取值 |
|---|---|---|---|
| `input.data.setl_id` | 字符型，30 | 必填 | 原结算响应的 `output.setlinfo.setl_id`，定位被撤销的结算 |
| `input.data.mdtrt_id` | 字符型，30 | 必填 | 原结算响应的 `output.setlinfo.mdtrt_id`，标识该次就诊 |
| `input.data.psn_no` | 字符型，30 | 必填 | 原结算响应的 `output.setlinfo.psn_no`，标识该次结算的人员 |
| `input.data.exp_content` | 字符型，4000 | 表 121 未标必填 | 承载协议约定的扩展内容 |

先读公共响应的数值字段 `infcode`。`0` 表示成功，`-1` 表示失败；失败时从 `err_msg` 读取业务错误信息。成功后，`output.setlinfo` 是一条结算主记录，`output.setldetail` 是基金分项数组，逐项读取 `output.setldetail[].fund_pay_type` 等字段。已参加定点医药机构费用结算的费用也允许撤销，反向结算金额参与下次医药机构费用结算。该交易章节未给出重复撤销的处理结果。
